# คู่มือการใช้งาน `/ecmis`

`/ecmis` คือผู้ช่วยใน Claude Code ที่ช่วยเติมและอัปเดตไฟล์ Excel **E-CMIS Master Activity Template** ให้ทีละ Activity
โดยอ่านข้อมูลจากเล่มเอกสาร (และ source code ถ้ามี) แล้วเขียนลงไฟล์ Excel ให้ พร้อมบอกที่มาของทุกข้อมูล

คุณไม่ต้องเขียนโค้ดหรือพิมพ์คำสั่งยาว ๆ แค่วางไฟล์ให้ถูกที่ แล้วสั่งคำสั่งเดียว ระบบจะพาทำครบทุกขั้น และจะหยุดถามคุณเฉพาะตอนที่ต้องตัดสินใจเท่านั้น

## 2. การติดตั้ง

ติดตั้งครั้งเดียวต่อเครื่อง

### Windows

1. แตกไฟล์ zip
2. ดับเบิลคลิก **`install.cmd`**
3. รอจนขึ้นข้อความ ✅ ว่าติดตั้งเรียบร้อย

### macOS

1. แตกไฟล์ zip
2. เปิดแอป **Terminal** ในโฟลเดอร์ที่แตกไฟล์ไว้ แล้วพิมพ์

   ```
   bash install.sh
   ```

3. รอจนขึ้นข้อความ ✅ ว่าติดตั้งเรียบร้อย

### ตัวติดตั้งทำอะไรให้บ้าง

- ติดตั้ง `/ecmis` ให้ใช้ได้ในทุกโปรเจกต์บนเครื่องนี้
- ติดตั้ง **ตัวแปลงเอกสาร (markitdown)** ให้ด้วย ถ้าเครื่องมี Python แล้ว
- ถ้าเคยติดตั้งเวอร์ชันเก่าไว้ ของเดิมจะถูกสำรองไว้ให้อัตโนมัติ

> 💡 **ถ้าขึ้นว่าไม่พบ Python** ให้ติดตั้ง Python ก่อน แล้วรันตัวติดตั้งอีกครั้ง
> ถ้าขึ้นว่าติดตั้งตัวแปลงเอกสารไม่สำเร็จ ก็ยังใช้งานต่อได้ ระบบจะเสนอติดตั้งให้อีกครั้งตอนใช้งานครั้งแรก

> 💡 ถ้าเปิด Claude Code ค้างไว้ก่อนติดตั้ง ให้ **ปิดแล้วเปิดใหม่** หนึ่งครั้ง

## 3. เตรียมโปรเจกต์และวางไฟล์

1. คัดลอกโฟลเดอร์ **`project/ecmis-trace`** จากไฟล์ zip ไปไว้ที่ที่ต้องการ เช่น Desktop หรือ Documents
2. วางไฟล์ตามตารางนี้

| โฟลเดอร์ | ใส่อะไร | จำเป็นไหม |
|---|---|---|
| `input/docs/` | **เล่มเอกสาร** (PDF / DOCX / PPTX / XLSX / รูปภาพ) — ถือเป็นข้อมูลหลัก | ✅ ต้องมี |
| `input/code/` | source code ของระบบ หรือไฟล์ข้อความที่บอกที่อยู่ของโค้ด | ไม่มีก็ได้ |
| `template/` | template Excel ต้นฉบับ (วางไว้ให้แล้ว) | ✅ **ห้ามแก้ไข** |

> ⚠️ ไฟล์รุ่นเก่า `.doc` / `.ppt` / `.xls` ให้เปิดแล้ว "บันทึกเป็น" `.docx` / `.pptx` / `.xlsx` ก่อน

> 💡 ถ้าวางเล่มผิดที่ (เช่นวางไว้นอกโฟลเดอร์ `input/docs/`) ไม่ต้องกังวล ระบบจะตรวจเจอและถามว่าจะให้ย้ายให้ไหม

ส่วนโฟลเดอร์ `work/` และ `output/` ระบบจะสร้างและใช้งานเอง ไม่ต้องแตะ

## 4. วิธีใช้งานทีละขั้น

### เริ่มงาน

เปิด Claude Code ในโฟลเดอร์ `ecmis-trace` แล้วพิมพ์ `/ecmis` ตามด้วยเลข Activity เช่น

```
/ecmis 5
```

ถ้าพิมพ์แค่ `/ecmis` โดยไม่ใส่เลข ระบบจะถามว่าจะทำ Activity ไหน

### ระบบจะทำอะไรบ้าง

ระหว่างทำงาน ระบบจะแจ้งความคืบหน้าเป็นระยะ เช่น `ขั้น 2/6 สกัดข้อมูล Activity 5…`

| ขั้น | ระบบทำอะไร | คุณต้องทำอะไร |
|---|---|---|
| **0. ตรวจความพร้อม** | ตรวจว่าไฟล์อยู่ครบและถูกที่ และตัวแปลงเอกสารพร้อมใช้ | ถ้าระบบถามว่าจะติดตั้งตัวแปลงเอกสารไหม ให้ตอบ **ตกลง** |
| **1. เตรียมเอกสาร** | แปลงเล่มเอกสารเป็นข้อความ (แปลงเฉพาะเล่มใหม่หรือเล่มที่มีการเปลี่ยน) | — |
| **2. สกัดข้อมูล** | อ่านเล่มแล้วดึงข้อมูลของ Activity นี้ออกมา | ⏸ **จุดตรวจ 1** (ดูด้านล่าง) |
| **3. เทียบกับโค้ด** | ตรวจข้อมูลหน้าจอกับ source code เช่น ปุ่ม สถานะ ข้อความแจ้งเตือน | ถ้าไม่มีโค้ด ระบบจะถามว่าจะ **ข้าม** หรือ **หยุดเพื่อวางโค้ดก่อน** |
| **4. อัปเดต Excel** | วางแผนว่าจะเพิ่ม/แก้/ลบอะไรในไฟล์ Excel | ⏸ **จุดตรวจ 2** (ดูด้านล่าง) |
| **5. ตรวจไฟล์** | ตรวจความถูกต้องของไฟล์ Excel อัตโนมัติ แล้วสรุปผล | — |
| **6. Playwright test** | ถ้า prototype ยังไม่มี test ตาม user flow ระบบจะไล่ดูรายละเอียดทุกหน้าจอ (Extracting screen details…) แล้วสร้าง test ที่เดินหน้าจอตาม flow ตรวจรายละเอียดและเก็บภาพหน้าจอทุกขั้น จากนั้นรันจนผ่าน | ⏸ **จุดตรวจ 3** (ดูด้านล่าง) แล้วอ่านสรุปท้ายงาน |

### ⏸ จุดตรวจ 1 — ตรวจข้อมูลที่สกัดได้

ระบบจะสรุปให้เห็นในหน้าแชท (ไม่ต้องเปิดไฟล์เอง):

- จำนวน Step / หน้าจอ / Transition / Test Case ที่ได้
- รายการที่ไม่ตรงกับข้อมูลร่างเดิม
- **คำถาม** ที่หาคำตอบในเล่มไม่เจอ พร้อมบอกว่ามาจากตรงไหน

จากนั้นให้เลือก

| ตัวเลือก | ความหมาย |
|---|---|
| **ไปต่อ** | ข้อมูลโอเค ไปขั้นถัดไปเลย คำถามที่ยังไม่ได้ตอบจะถูกบันทึกเป็น Open Issue ให้ไปหาคำตอบภายหลัง |
| **ขอตอบคำถามก่อน** | พิมพ์คำตอบที่ทราบ ระบบจะบันทึกไว้เป็นที่มาของข้อมูล แล้วค่อยไปต่อ |
| **หยุดไว้ก่อน** | พักงานไว้ กลับมาทำต่อทีหลังได้ |

### ⏸ จุดตรวจ 2 — ยืนยันก่อนแก้ไฟล์ Excel

**ระบบจะไม่แก้ไฟล์ Excel จนกว่าคุณจะยืนยัน** โดยจะแสดง:

1. ตารางสรุปจำนวนรายการ เพิ่ม / แก้ / ลบ / Open Issue ใหม่ แยกตามแท็บ
2. **รายการที่จะลบ** (แสดงก่อน เพราะสำคัญที่สุด) พร้อมเหตุผล
3. รายการที่จะแก้ แสดงค่าเดิม → ค่าใหม่ และที่มา
4. รายการที่จะเพิ่ม
5. รายการที่ข้ามไป เพราะยืนยันแล้วหรือมีผลทดสอบแล้ว

จากนั้นให้เลือก

| ตัวเลือก | ความหมาย |
|---|---|
| **ยืนยันทั้งหมด** | เขียนลงไฟล์ตามแผน |
| **ยืนยัน แต่ไม่ลบ** | เพิ่มและแก้ตามแผน แต่ไม่ลบอะไร รายการที่จะลบเปลี่ยนเป็น Open Issue ให้ตรวจสอบแทน |
| **ขอแก้บางรายการ** | บอกรหัสรายการที่ต้องการตัดออกหรือเปลี่ยน ระบบจะปรับแผนแล้วถามใหม่ |
| **ยกเลิก** | ไม่แก้ไฟล์ จบงานรอบนี้ |

### ⏸ จุดตรวจ 3 — ยืนยันก่อนเพิ่ม test ลง prototype

ขั้นนี้จะทำเมื่อมี prototype ใน `input/code/` เท่านั้น ถ้า prototype มี test ตาม user flow ครบแล้วระบบจะข้ามให้เอง

ระบบจะแสดงรายการ flow และหน้าจอที่จะทดสอบ แหล่ง user flow ที่ใช้ (เอกสารในตัว prototype) หน้าจอที่หาไม่เจอ และไฟล์ที่จะเพิ่มลง prototype จากนั้นให้เลือก

| ตัวเลือก | ความหมาย |
|---|---|
| **สร้าง test เลย** | สร้าง test แล้วรันจนผ่านทั้งหมด |
| **ขอตอบคำถามก่อน** | ตอบคำถามเรื่อง flow ที่เอกสารไม่ชัด แล้วค่อยสร้าง |
| **ข้ามขั้นนี้** | ไม่เพิ่มอะไรลง prototype |

ระบบ **ไม่แก้หน้าจอของ prototype** ถ้าเจอจุดที่ prototype ไม่ตรงกับ flow จะรายงานไว้ให้ในสรุปท้ายงาน

ถ้าต้องการทำเฉพาะขั้นนี้ (Excel ทำเสร็จแล้ว) สั่ง

```
/ecmis 5 test
```

### ทำ Activity ถัดไป

ระบบทำครั้งละ 1 Activity และจะหยุดรอหลังจบงาน เมื่อตรวจผลแล้วให้สั่ง Activity ถัดไปเอง เช่น

```
/ecmis 6
```

### ถ้างานค้างกลางทาง

สั่งเลขเดิมซ้ำได้เลย เช่น `/ecmis 5` ระบบจะ

- ข้ามการแปลงเล่มที่ไม่ได้เปลี่ยน
- ถามว่าจะใช้ผลที่ทำไว้แล้ว (แนะนำ) หรือทำใหม่

ถ้ามีการเพิ่มหรือเปลี่ยนเล่มเอกสาร ให้วางไฟล์ใหม่ใน `input/docs/` แล้วสั่ง `/ecmis <เลข>` อีกครั้ง ระบบจะอัปเดตไฟล์ Excel เดิมตามเล่มฉบับใหม่ให้

## 5. ผลลัพธ์ที่ได้

### ไฟล์ Excel ที่ส่งมอบ — มีไฟล์เดียว

```
output/ECMIS_Master_Activity_Template_FlowScreenTrace.xlsx
```

ทุก Activity ถูกเติมลงไฟล์นี้ไฟล์เดียว ครั้งแรกระบบจะคัดลอกมาจาก template ครั้งต่อ ๆ ไปจะอัปเดตไฟล์เดิมเสมอ

### ดูยังไงว่าอะไรเปลี่ยน

| สิ่งที่เห็นในไฟล์ | ความหมาย |
|---|---|
| ช่องไฮไลต์ **สีเหลืองอ่อน** | ช่องที่ถูกแก้ในรอบล่าสุด |
| แถวไฮไลต์ **สีเขียวอ่อน** | แถวที่เพิ่มใหม่ในรอบล่าสุด |
| แท็บ **`18_Change_Log`** | ประวัติการเปลี่ยนแปลงทุกครั้ง: ค่าเดิม → ค่าใหม่, ที่มา, เหตุผล และข้อมูลของแถวที่ถูกลบ |
| แท็บ **`10_Open_Issue`** | คำถามหรือจุดที่ข้อมูลไม่ครบ/ไม่ตรงกัน ที่ต้องให้ผู้รู้ตอบ |

ไฮไลต์ของรอบก่อนจะถูกล้างออกเมื่อเริ่มรอบใหม่ จึงเห็นเฉพาะสิ่งที่เปลี่ยนในรอบล่าสุดเสมอ

### ข้อมูลทุกช่องมีที่มา

ระบบ **ไม่เดาข้อมูล** ทุกช่องที่เติมจะระบุที่มาไว้ เช่น

- `ชื่อเล่ม น.12` — หน้า 12 ของเล่ม PDF
- `ชื่อเล่ม สไลด์ 8` — สไลด์ที่ 8 ของ PowerPoint
- `ชื่อเล่ม §ชื่อหัวข้อ` — หัวข้อในไฟล์ Word
- ต่อท้ายด้วย `[อ่านจากภาพ]` — ข้อมูลที่อ่านจากภาพสแกน **ควรให้คนตรวจทานอีกครั้ง**

ถ้าหาข้อมูลในเล่มไม่เจอ ระบบจะเว้นช่องว่างไว้ และเปิดรายการใน `10_Open_Issue` แทน
ถ้าเล่มกับโค้ดไม่ตรงกัน ระบบจะใช้ค่าจากเล่ม และเปิด Open Issue ระบุทั้งสองค่าให้ตรวจสอบ

### ข้อมูลที่ระบบจะไม่แตะ

- แถวที่มีสถานะ **"ยืนยันแล้ว"**
- ผลทดสอบที่กรอกไว้แล้ว: `Actual Result`, `Test Result`, `Step Result`, `Defect ID`
- ไฟล์ template ต้นฉบับ

### ไฟล์สำรอง

ก่อนแก้ไฟล์ Excel ทุกครั้ง ระบบจะสำรองไฟล์เดิมไว้ที่ `output/backup/` โดยใส่วันเวลาในชื่อไฟล์ เช่น

```
ECMIS_Master_Activity_Template_FlowScreenTrace_20260921-1530.xlsx
```

ถ้าผลรอบล่าสุดไม่ถูกต้อง สามารถนำไฟล์ในนี้กลับมาใช้แทนได้

### สรุปท้ายงาน

เมื่อจบแต่ละ Activity ระบบจะสรุปในแชทว่า

- เขียนอะไรลงไปบ้าง แยกตามแท็บ และชื่อไฟล์สำรอง
- ผลการตรวจไฟล์ **ผ่าน / ไม่ผ่าน** (ถ้าไม่ผ่านจะบอกว่าตรงไหนและควรแก้อย่างไร)
- **Playwright test** ที่เพิ่มลง prototype, ผลรัน, ที่เก็บภาพหน้าจอ และจุดที่ prototype ไม่ตรงกับ flow
- **Open Issue ที่เปิดใหม่** — สิ่งที่คุณต้องไปหาคำตอบ
- หน้าที่อ่านจากภาพ — จุดที่ควรให้คนตรวจทาน
